# LabelCropTools — free browser tools for Indian e-commerce sellers

21 free, client-side tools for Meesho / Flipkart / Amazon sellers: label croppers (auto-detect,
invoice removal, SKU/courier sorting, thermal 4×6 or A4 2/4-up, SKU+Qty stamp), picklist generator,
PDF tools (drag-crop, pages-per-sheet, merge, split, rotate/delete, images↔PDF), calculators
(profit after fees, GST, volumetric weight) and generators (bulk barcode sheets, UPI/WhatsApp QR,
thank-you cards, GST invoice PDF) plus image resize/compress.

**Nothing is uploaded.** PDF.js + pdf-lib + Canvas run in the browser; the site is fully static.

## Quick start

```bash
npm run build      # → dist/  (HTML, sitemap, robots, manifest, OG images, icons)
npm run serve      # http://localhost:8787
```

Requirements: Node ≥ 18, Python 3 with Pillow (only for OG images / icons; the HTML build works without it).

## Adding a tool

1. Add an entry to `src/tools.mjs` (slug, category, title ≤ 65 chars, description, tagline,
   keywords, `panel` markup, steps, benefits, features, faq, related).
2. Create `src/assets/js/tools/<script>.js`. Use `SKUD.dropzone`, `SKUD.lib('pdflib')`,
   `SKUD.download`, `SKUD.status`.
3. `npm run build && node scripts/audit.mjs`.

## Blog: the Seller Playbook

15 long-form guides (about 17,000 words) organised into three marketplace silos, each one
funnelling to the tools it references.

```
/blog/                      index, grouped by marketplace
/blog/meesho|flipkart|amazon/   hub page per silo
/blog/<post-slug>/          the article
/blog/rss.xml               feed
```

The index is an editorial mosaic: an inverted lead card spanning the full height, a tinted
feature with two stacked row-links, a white secondary, a tall story and a topics tile. It is a
three-column grid with flex columns inside, so the cards bottom-align at any width instead of
relying on fragile grid row spans. Hub pages reuse the same lead card horizontally. All of it is
built from the existing tokens (`--cta`, `--accent-2`, `--surface`, `--card`), so the section
inverts correctly in dark mode with no extra colour definitions.

Articles live in `src/posts/*.mjs`, one file per post, and register themselves in
`src/posts/index.mjs`. Each exports frontmatter (title, metaTitle, description, keyword,
published/updated dates, related tool slugs, FAQ) plus a markdown `body`. A ~90-line renderer in
[`src/markdown.mjs`](src/markdown.mjs) handles headings, lists, tables, blockquotes and links, so
there is no CMS and no markdown dependency.

Each article page generates BlogPosting + BreadcrumbList + FAQPage JSON-LD, its own 1200x630 OG
image, a table of contents from the H2s, a related-tools grid and related-posts links. Hub pages
emit Blog schema. Everything lands in the sitemap and RSS automatically.

### Cover art

Every article has original cover art generated by [`scripts/make-covers.py`](scripts/make-covers.py),
which runs automatically as part of `npm run build`. There is no stock photography and no
third-party imagery: each cover is a geometric diagram drawn from the site's own palette, with a
motif chosen per article (`label-crop`, `chart`, `funnel`, `box`, and so on) set in the post's
`cover` field.

The art is deliberately **textless**. The headline sits next to the image in HTML, so putting it
in the artwork as well would duplicate it for readers and crawlers alike.

Each post also carries an authored `coverAlt` describing what the diagram shows, rather than
repeating the title. Covers are emitted at 1200x750 and 600x375 in both WebP and PNG, served
through `<picture>` with `srcset`/`sizes`, explicit `width`/`height` (so CLS stays at zero),
`loading="lazy"` below the fold and `fetchpriority="high"` on the article hero. They are cached
immutably and versioned by build id, and the article's `BlogPosting` schema points at the 1200px
PNG as an `ImageObject`.

`npm run audit` fails on any `<img>` missing `alt` or `width`/`height`, and resolves every
`srcset` candidate as well as the fallback `src`.

**Writing note:** the guides cite only verifiable sources (CBIC GST rules, NPCI's UPI spec, GS1,
W3C) and first-hand testing. No invented statistics or fabricated studies. Fee percentages are
shown as illustrations with an explicit instruction to confirm current rates in the seller panel,
because marketplace fee schedules change.

`npm run check:posts` enforces the editorial rules: no em dashes, no AI filler phrases, minimum
length, keyword in title / first 100 words / an H2, meta-title and description limits, at least
two internal links, an FAQ, and paragraph and list-item length caps.

### Adding an article

1. Copy an existing file in `src/posts/`, change the frontmatter and body.
2. Import and add it to the array in `src/posts/index.mjs`.
3. `npm run check` (builds, audits, checks contrast and editorial rules).

## Design system

Soft **bento** language: a silver page surface with a light radial wash, white cards with hairline
borders and soft elevation, large radii (24 / 34 px), fully rounded pills, a black primary CTA and
a blue accent. Display type is **Outfit**, body is **Instrument Sans**, numerals/labels **IBM Plex
Mono** — all self-hosted.

Everything is driven by tokens in the `:root` block of [`main.css`](src/assets/css/main.css):
`--paper` / `--surface` / `--card` for the three surface levels, `--cta` + `--cta-ink` for the
primary button (it inverts in dark mode), `--accent` for highlights, `--line` / `--line-field` for
hairlines vs control borders, and `--shadow-sm` / `--shadow` / `--shadow-lg` for elevation. Change a
token and the whole site follows — the home page, every tool UI and the generated OG images.

`npm run contrast` re-checks 40 foreground/background pairs against WCAG AA in **both** themes and
reads the tokens straight from the stylesheet, so a palette change can't silently break contrast.

## Hero brand rotator

The H1 reads "Free tools for [logo] sellers." and the slot cycles through the marketplaces,
morphing its width to each logo's aspect ratio. The full phrase stays in the heading as
screen-reader text, so the H1 still reads *"Free tools for Meesho, Flipkart & Amazon sellers."*
for crawlers. It pauses off-screen, in background tabs, and on hover, and drops the 3-D flip
under `prefers-reduced-motion`.

**To add or replace a logo:**

```bash
# 1. drop the artwork in logos/ named after the brand slug
cp ~/Downloads/amazon.png logos/amazon.png
# 2. trim + remove background + resize
npm run logos
# 3. rebuild
npm run build
```

`scripts/prep-logos.py` flood-fills from the border using an absolute "light and unsaturated"
test, so anti-aliased edges don't leak into letterforms and interior highlights survive. It
works on logos that sit on a white or light background. For a logo on a dark background, tune
`min_v` / `max_sat` in `flood_background()`, or supply a PNG that already has an alpha channel —
existing transparency is respected and only trimmed. Sources with a banner or reflection can be
pre-cropped via the `PRECROP` map (the bundled Flipkart banner uses it).

Brands, their order, and the interval live in `src/site.config.mjs` (`brands`, `brandRotateMs`).
A brand with no processed image falls back to a wordmark in the site's own typeface.

Marketplace logos are used only to indicate which label formats the tools support; the footer and
every tool page carry a "not affiliated" disclaimer. Swap or remove them in `brands` if you'd
rather not display them.

## Security headers

`_headers` (honoured by Cloudflare Pages and Netlify) sets HSTS, a CSP, `X-Content-Type-Options`,
`X-Frame-Options`, `Referrer-Policy` and `Permissions-Policy`. The CSP is also emitted as a
`<meta>` tag so it applies on hosts that ignore `_headers` and during local testing. Inline scripts
are allow-listed by SHA-256 hash, so the policy never needs `'unsafe-inline'` for scripts — if you
add an inline script, rebuild so its hash is picked up, or it will be blocked.

## Deploy

Deployed to **Cloudflare Workers Static Assets** (not Pages — Cloudflare recommends Workers for
new projects, and Pages only receives maintenance now). Config lives in `wrangler.jsonc`.

```
npm run deploy      # runs the full check suite, then wrangler deploy
```

There is no Worker script: `assets.directory` points at `dist/` and Cloudflare serves it from the
edge, so no Worker invocations are billed. Three settings are deliberate:

| Setting | Why |
| --- | --- |
| `not_found_handling: "404-page"` | Workers does not infer this the way Pages did; without it, unmatched paths return a bare 404 instead of `404.html` |
| `html_handling: "auto-trailing-slash"` | Serves `<slug>/index.html` at `/<slug>/`, matching the canonical URLs. Stated explicitly so a default change cannot silently alter them |
| `workers_dev: false` | Stops the site being reachable at a second `*.workers.dev` address that Google could index as duplicate content |

`_headers` is read by Workers and applied to asset responses (limits: 100 rules, 2,000 chars per
line — this site uses 6 rules and a 409-char maximum). `dist/.assetsignore` keeps the build-time
`og-manifest.json` and `cover-manifest.json` out of the upload.

`dist/` is not committed. Deploys upload the locally built output, so the machine that deploys
needs Python 3 with Pillow for the OG images and blog cover art. To build from CI instead, the
build command is `pip install Pillow && npm run build` with output directory `dist`.
